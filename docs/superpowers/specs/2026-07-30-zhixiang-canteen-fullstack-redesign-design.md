# 「智饷」高校智慧食堂 B/C 端全链路改造设计文档

- 日期：2026-07-30
- 状态：已通过用户确认（方案 A · 两阶段交付）
- 范围：`zhixiang/`（canteen C 端 / management B 端 / server 后端）

## 1. 背景与现状诊断

整体完成度约 40%。后端 Express + SQLite 可运行，骨架完整；但核心就餐闭环（支付、取餐、订单感知）基本缺失，安全体系为零，约一半接口返回硬编码假数据。

关键结构性问题：

1. **C 端两套前端割裂**：`canteen/zhixiang.html` 设计感强但数据全硬编码；`canteen/index.html` + `script_v3_api.js` 接了真实 API 但 UI 朴素、功能残缺（搜索/筛选/详情容器留好但 JS 未写）。
2. **支付 0%**：无支付界面、无支付接口；用户余额字段 `jine` 存在但从不动。
3. **取餐 0%**：无取餐码生成/核销；`showNotification` 只 `console.log`，下单成功等所有反馈用户不可见（`script_v3_api.js:657-660`）。
4. **联动"写通读不通"**：B 端改订单状态真实落库，但 C 端无"我的订单"页，感知不到；B 端留言答复 C 端无展示入口。
5. **安全为零**：密码明文、伪 token 且全接口无鉴权、任何人可删菜改单、CORS 白名单仅 `localhost:8000`。
6. **B 端三模块纯 mock**：食品安全、节约校园、商户审核为静态假数据（本次按用户决策保留展示、标注"规划功能"，不做实）。
7. **AI 为 Gemini 单点调用 + mock 降级**，`.env` key 为占位符（本次按用户决策保持 mock 并打磨）。
8. 孤儿/冗余文件：`script.js`、`script_v2.js`、`styles.css`、`zhixiang2.html`、`startup1.bat`、`management/zhixiang.html`；`index.html:14` 引用不存在的 `logo.svg`。

## 3. 目标效果

### 3.1 C 端用户动线

1. 首页「风格宇宙」选择器：动漫次元 / 影视光影 / 音乐现场 / 电竞赛博 / 国风墨韵 / 爱豆应援 / 运动活力 / 极简留白等选项卡（SVG/渐变/纹样原创绘制）。
2. 选定后全站换肤（主色/渐变/卡片纹样/按钮形态/吉祥物 emoji/文案彩蛋），个性化推荐以该风格人设推菜（如"运动活力"推高蛋白低脂餐）。
3. 菜品浏览：搜索、分类筛选、详情弹层全部生效；加购数量合并、localStorage 持久化。
4. 结算：订单确认页（清单/备注/取餐食堂）→ 收银台（余额展示 + 支付确认动画）→ 扣款成功 → 取餐码页（大字号取餐码 + 状态时间线）。
5. 我的订单：3 秒轮询，状态 `已支付→制作中→待取餐→已完成` 实时更新，"请取餐"高亮脉冲。
6. 全程 toast 通知真实可见。

### 3.2 B 端管理动线

管理员登录 → 订单管理接单 → 制作完成叫号 → C 端实时变"请取餐" → 学生出示取餐码 → B 端核销 → 闭环。菜品管理补上下架开关与库存预警；数据大屏硬编码指标真实化。

## 4. 技术设计

### 4.1 后端（server/）

- **订单状态机**：`未支付→已支付→制作中→待取餐→已完成`，分支 `已退款/已取消`；`PUT /orders/:orderid/status` 校验非法流转并返回 409。
- **`POST /orders/:orderid/pay`**（新增）：事务包裹——校验余额与库存 → 扣减 `yonghu.jine` → 扣减 `kucun` → 状态置"已支付" → 生成 4 位取餐码写入 `orders.pickup_code`（ALTER TABLE 加列，含迁移逻辑）。
- **`POST /orders/:orderid/pickup`**（新增）：B 端核销，校验取餐码后状态置"已完成"。
- **鉴权**：bcrypt 密码哈希（含种子数据迁移）；登录签发带签名 token；写接口（菜品 CUD、订单状态、留言回复、支付、核销）挂校验中间件；`yonghu` 表加 `role` 字段，admin 接口校验角色。
- **修复**：CORS 白名单支持 8000 及管理端端口并读取 `CORS_ORIGIN`；`GET /orders/:orderid` 查不到返回 404；下单事务化。
- **AI mock 打磨**：`/ai/chat` 与 `/ai/analyze-nutrition` 的降级分支基于真实菜品库做关键词 + 营养标签匹配。
- **smoke 测试脚本**：`server/scripts/smoke.js`，跑通 注册→登录→浏览→下单→支付→接单→叫号→核销 全链路断言。

### 4.2 C 端（canteen/）

- 以 `zhixiang.html` 为壳拆分为 `index.html` + `app.js` + `themes.css`；内嵌 `DB` 假数据全部替换为 `http://localhost:5000/api` 真实调用；`apiCall` 携带 Authorization 头。
- 新增视图：注册、订单确认、收银台（余额支付）、取餐码、我的订单（3s 轮询 + 状态时间线）、个人中心（资料保存接 `PUT /users/:id`）。
- 修复：`showNotification` 改为真实 toast 组件；购物车同款合并 + localStorage 持久化；`logo.svg` 裂图。
- 主题系统：`data-theme` 属性 + CSS 变量包，约 10 套主题；选择存 localStorage；主题与推荐联动（主题人设 → 菜品标签过滤 + 推荐文案）。
- 清理：删除 `script.js`、`script_v2.js`、`styles.css`、`zhixiang2.html`、`startup1.bat`；旧 `index.html`/`script_v3_api.js`/`styles_v2.css` 在新壳验证通过后替换下线。

### 4.3 B 端（management/）

- 管理员登录页 + token 鉴权（替换写死的"管理员"）。
- 订单管理升级：接单（已支付→制作中）→ 叫号（→待取餐）→ 取餐码输入核销（→已完成）。
- 菜品管理：上下架开关（`status` 字段）、库存预警（低库存高亮）。
- 数据大屏：硬编码 KPI（注册学生数、后勤指标看板）替换为真实统计接口。
- 移出误放的 `zhixiang.html`；食安/节约/商户模块标注"规划功能"。

### 4.4 错误处理

- 后端统一错误格式 `{code, message}`；余额不足/库存不足/非法状态流转返回明确业务错误码。
- 前端 `apiCall` 统一拦截 401 跳登录、业务错误 toast 展示。

### 4.5 验证

- 后端：`npm run smoke`（新增脚本）全链路断言通过。
- 前端：按 3.1 / 3.2 动线人工走查；换肤、轮询、支付、核销逐步验证。
- 回归：B 端菜品 CRUD、留言回复既有功能不受影响。

## 5. 两阶段交付

- **阶段 1「链路闭环」**：4.1 全部 + 4.2 的 API 接入与新增视图 + 4.3 的登录/订单操作流/上下架。产出：完整可演示的就餐闭环。
- **阶段 2「体验与卖点」**：主题换肤系统 + 个性化推荐首页 + UI/动效打磨 + 数据大屏真实化 + 文件清理收尾。
