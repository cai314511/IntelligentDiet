# 智饷系统实现状态

## 页面与功能

学生与校方共用根目录登录入口，按学校、校区及身份路由。开发入口仅自动填入管理员凭据，仍由用户提交登录；两端退出与登录过期返回同一入口。支持中央财经大学、天津大学、北京林业大学，页面校名、年份和新增控件的品牌色读取学校配置。

学生端沿用现有页面配色、圆角卡片与顶部栏目名称。首页提供小智规划、按菜找食堂、按食堂找菜及直接加入餐盘四种入口，两条菜单路径分别保存筛选状态。风格宇宙位于系统设置。手机端通过功能菜单进入全部栏目。

小智全屏入口使用透明主体、蓝灰色动态背景和任务步骤。方案包含菜品、食堂、窗口、距离、排队、座位、费用及时间，支持修改与取消，确认后创建未支付订单；支付使用独立费用确认。任务写入数据库；进入小智页面开启新对话，不自动展示或执行历史订单。对话补全就餐需求后生成待确认方案，任务进度由服务端执行事件更新。自然语言支持中文人数、预算及明日时刻；开场及追问由模型按系统提示词和对话上下文生成，模型决定继续询问或生成方案，对话主流程不使用快捷选择和固定问题；更换需求使旧方案失效，编辑保留座位并支持取消预约，页面退出后忽略旧请求结果。直接点餐与推荐方案共用订单确认和收银台，均支持时间与座位选择，座位加载完成后才允许确认，取消后的同座同时段可以再次预约。小智的九种场景素材尚未逐一制作成独立动画。

营养页面支持菜品搜索、实际份量记录、自填食物、14天记录、基础评分与营养结构、照片预览及识别后校对。管理员具有高级权限，其他账户显示锁定权益。目标、忌口、口味和宏量比例可持久保存；高级功能首次使用建立偏好。照片识别需要配置支持图像输入的模型。

后勤端提供日期、校区、食堂及窗口上下文，展示订单统计、小时／日／周趋势、上一周期、经营目标、同校区对比、排队和反馈。供需预测单独提供时段需求、就餐人次、备餐与采购缺口、预计浪费、成本节省和回测指标。

订单按整单分组，支持状态筛选、接单、叫号、核销及退款。供应商、库存批次、采购、安全、节约和服务台账支持编辑、归档、审计及撤销。另有菜品元信息维护、上下架、反馈闭环、评价回复、活动报名管理及文创履约页面。通用表格支持搜索、排序、分页、导出、选择、批量操作及固定操作列，手机使用抽屉导航和横向表格。

## 数据与模型边界

前端业务模块位于 `canteen/features/` 和 `management/features/`，通用请求与状态组件位于 `shared/`，独立REST API位于 `server/`。页面使用统一请求配置及鉴权、超时和GET重试；接口失败显示错误状态。原固定营养报告、模拟语音流程和后勤假成功回退已移除。

`userdata/` 保存三校配置、98条参考菜单、运营初始化信息和本地SQLite数据库。数据库、密钥与环境配置不提交。菜单和营养字段显示来源与时间，商品信息及运营指标可由管理员维护。

模型采用 DeepSeek 官方地址的 Responses API，模型为 `deepseek-v4-flash`，推理强度为 `medium`；密钥仅从 `DEEPSEEK_API_KEY` 环境变量读取，可在 Git 忽略的 `server/.env` 填入。遇到模型不存在错误先查询同一地址的模型列表，不自动改模型或协议。参数为空时小智对话返回未配置状态，不用固定问题代替模型；菜品与座位方案由数据库规则计算，营养基础报告按个人记录计算；照片识别返回未配置状态，用户可手动记录。供需预测目前采用历史日均销量，并对末7天留出数据计算误差；历史量或成本不足时相关指标为空，不生成固定准确率或节省金额。

实际会员支付、外部校园认证和网页部署尚未接入。学校专属校徽与背景素材可继续补充到学校配置。

## 验证

64项接口回归通过，覆盖身份与学校隔离、营养权限与份量计算、方案确认和重复执行、直接点餐价格变更确认、订单支付退款核销、座位冲突、积分回滚、预测回测、台账审计撤销，后勤订单的校区、食堂、窗口字段，以及台账负成本与跨校关联校验。

浏览器验证了统一登录、小智生成与修改方案、座位选择、确认创建未支付订单、独立支付确认、后勤订单同步、筛选与预测页面、营养记录搜索、手机导航；小智新对话入口、需求追问、共用结算以及刷新不带入历史订单。支付扣款和取餐核销的资金／库存行为通过隔离数据库接口测试验证。JavaScript语法与Git空白检查通过。

### 小智对话回归

对话区分补充条件、准备方案、回答已有方案问题、取消草稿四类意图。提问由模型生成；只询问尚未明确的信息。菜单与执行状态来自当前学校数据库，订单状态查询包含实际支付状态。预算按总额计算，忌口与饮食限制参与后端筛选，过去时间不能进入执行。

运行 `node scripts/test-agent-live.mjs` 可使用本地 DeepSeek 配置进行22项真实模型回归，脚本使用独立内存数据库；覆盖多轮补充、自然语言修改、方案问答、忌口解除、低预算、无匹配菜品、时间、学校隔离、订单确认与幂等、取消以及查询支付状态。普通回归使用 `npm test`，不调用外部模型。

浏览器检查覆盖主动开场、处理中反馈、完整方案、聊天修改、共用确认页、自然语言取消、服务中断后保留方案及重试。语音已处理不支持、启动失败、权限错误和过期回调；实际麦克风识别尚需在支持语音的浏览器中验收。当前智能方案每人同一道菜，混合多菜需求会引导分别规划。

小智方案与手动菜品统一加入餐盘，通过同一订单与收银台入口结算；食堂座位图支持切换食堂、时间和点击选座，用餐安排回填至结算页。

座位目录按单人座管理，每个食堂96个座位，提供楼层和ABCD区域筛选；绿色可选、淡黄色不可选、红色已选，多人预约按人数校验座位数量。

小智聊天卡片统一提供新对话和历史对话入口，对话按账号及学校保存到userdata数据库，支持查看和恢复继续聊天。
