# 拉取后复现本地运行状态

## 首次启动

推荐使用与本次发布一致的 Node.js 26.10.0（仓库 `.nvmrc` 已记录）。进入仓库根目录后：

```sh
npm run setup
npm start
```

打开 http://localhost:8000/，选择学校、校区及身份登录。开发入口的“自动填入管理员账号”可进入对应学校。前端 8000、API 5010，避开 macOS 常见的 5000 端口占用。

`setup` 使用已提交的 `server/package-lock.json` 安装依赖，校验并恢复数据库快照，再从 `.env.example` 创建本机环境配置。`start` 同时启动前后端，终止时关闭两个子进程。

## 已同步内容

- 三校菜单、份量、营养、价格、楼层、餐厅及座位配置。
- 图片和校园主题素材，包括中财及北林专属页面、小智图集、菜品与文创图片。
- 数据库中的账号、订单、口味画像、饮食记录、会员、积分、文创、社区、座位预订、对话及后勤业务台账。
- 当前数据库一致性快照：`userdata/snapshots/local-state.db`。
- 资产校验值、数据库校验值及表记录数量：`userdata/snapshots/manifest.json`。

运行数据库 `userdata/zhixiang.db` 不直接提交，首次运行由快照恢复；历史备份、日志和本机生成文件不参与复现。资产及原始素材均随 Git 同步，不依赖仓库外的桌面文件夹。Python 数据审计工具属于维护工具，网页运行不依赖 Python。

## 已有副本更新

`git pull` 后会获得最新代码、素材与发布快照。`npm run setup` **保留已有运行数据库**，不会覆盖合作者已经产生的业务数据。若明确需要完整恢复本次发布的数据状态，先关闭服务，把已有 `userdata/zhixiang.db` 及可能的 `-wal`、`-shm` 文件移到仓库外备份，然后重新执行 `npm run setup`。

## 在线 AI 与本机状态

在 `server/.env` 填写 `DEEPSEEK_API_KEY` 后重启服务，使用 `deepseek-v4-flash`。API 密钥及 JWT 签名密钥不提交到 GitHub；本机 JWT 密钥自动生成，合作者需重新登录。未填在线 AI 密钥时不能复现远程模型响应，系统保留本地菜单检索与规则规划。

浏览器的当前会话、未提交输入、餐盘草稿及界面偏好属于浏览器存储，不包含在数据库快照中。学校皮肤在登录后按账号学校自动绑定。排队状态、实时日期、供餐时段和模型回复会随实际运行时间变化；快照复现的是发布时的业务数据及页面实现。

不要运行 `import-menu` 来复现本次数据库：该命令用于主动刷新菜单，并非恢复快照所需步骤。
